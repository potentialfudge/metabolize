# metabolize

A web app for running Bayesian optimization (BO) campaigns for chemical reaction
optimization, with a **meta acquisition function blender** that
continuously blends acquisition functions Upper Confidence Bound (UCB),
Expected Improvement (EI), and Probability of Improvement (PI), with the blend weights derived from the
campaign's own statistics rather than fixed values.

**Live app:** https://metabolize.streamlit.app

---

## What this does

Instead of picking one acquisition function (or hand-tuning a schedule)
for a Bayesian optimization campaign, this app runs a **self-deriving meta
blender**: each round, it computes a continuous convex blend over UCB / EI /
PI, where the blend is governed by in-campaign signals (roughness,
uncertainty, stall, dispersion, improvement) whose influence is itself
estimated from how predictive each signal has been of improvement, so far,
in that specific campaign.

The app wraps this method in a per-round campaign workflow:

- Define your parameters (categorical or continuous, with optional
  discretization) and a (single) target to optimize
- Generate an initial batch via a Sobol sequence, or upload your own
- Enter results directly in an editable table (or download/upload a CSV)
- Get the next round's recommendations, generated by fitting a Gaussian
  Process (GP) surrogate and scoring candidates with the meta-blended acquisition
- Track progress with an always-visible statistics panel: learning curves,
  best-so-far, acquisition weight trajectories, per-parameter analysis
- Resume a campaign anytime: close the tab, come back later, pick up
  exactly where you left off

## Privacy

Every user's campaigns are private by default, enforced at the database
level via Postgres Row Level Security (RLS).
Neither other users nor the app's operator can read another user's campaign
data through the app. See [`db/schema.sql`](db/schema.sql) for the actual
policies.

## Simple vs. Advanced mode

- **Simple mode**: batch size, rounds, init method, parameters, target - 
  encoding is picked automatically (one-hot for categorical, none needed for
  continuous, SMILES auto-detected for chemical structure strings).
- **Advanced mode**: everything in simple mode, plus explicit per-parameter
  encoding control (one-hot vs. SMILES/Morgan fingerprint), and a
  **downloadable standalone runner script** — a self-contained Python script
  (no web app, no login) that runs the same campaign loop
  entirely in your own terminal/IDE, saving results and statistics to local
  folders as you go.

## Architecture

| Layer | Technology |
|---|---|
| UI | Streamlit |
| Identity | Auth0 (Google + email/password), via `st.login()` |
| Database | Supabase (Postgres), storage-only - Auth0 tokens verified via Supabase's Third-Party Auth |
| Privacy | Postgres Row Level Security, keyed on the Auth0 JWT's `sub` claim |
| Optimization | [BayBE](https://github.com/emdgroup/baybe) for search-space definition; a raw BoTorch `SingleTaskGP` fit directly for the acquisition surrogate |
| Meta blender | `core/meta_blender.py` — self-contained, no external dependencies beyond numpy/pandas |

Identity (Auth0) and storage (Supabase) are separate systems:
Auth0 handles who you are, Supabase enforces what you can see, connected via
Supabase's Third-Party Auth trusting Auth0-issued JWTs.

## Running locally

The web app itself (with login features and database) is only meant to run as the
single hosted instance at the link above. There is currently no supported path for
another user to stand up their own copy with a separate Auth0/Supabase
backend.

The **standalone runner script** can run locally, and it is available
in advanced mode. From a campaign's advanced-mode setup page, download a
self-contained Python script for that specific campaign, with exact instructions on how
to run it. It runs the same optimization loop (Sobol init, GP-fit
meta blender recommendations, round-by-round) fully offline in
your own terminal or IDE, pausing each round for you to enter your
experimental results, and saving results and statistics (learning curves,
distributions, per-parameter analysis) to local CSVs and PNGs as it goes.

```bash
pip install baybe torch gpytorch botorch scipy pandas numpy matplotlib
python your_campaign_runner.py
```

(place the downloaded script alongside a `core/` folder containing
`baybe_integration.py`, `meta_acquisition_blender_evalue_f.py`, and
`acquisition_switcher.py`)

## The meta blender

The core optimization logic lives in
[`core/meta_blender.py`](core/meta_blender.py),
fully documented in its own module docstring. Briefly: each batch, it calculates

```
score(x) = a_UCB · UCB(x) + a_EI · EI(x) + a_PI · PI(x)      a ≥ 0, Σa = 1
```

where the explore/exploit weight driving `a` is computed from campaign
signals (roughness, uncertainty, stall, dispersion, improvement), and the
influence of each signal is Bayesian-shrunk between a principled prior and
what the campaign's own data supports — so the method is reliable from the
very first batch (cold start = prior) and sharpens as evidence accumulates,
without ever training on data outside the current campaign.

It also includes a secondary, read-only anytime-valid e-value stopping
monitor, and a stall-escape mechanism with runaway guards (cooldown, reset
cap, convergence gating) to avoid wasting budget on random resets once a
campaign has plateaued near its optimum.
